# xsub — X(Twitter) / YouTube 视频字幕提取 + 中文学习摘要

复制视频链接，终端一条命令，得到完整字幕和学习摘要。音视频下载与转写全程在本机完成，不上传音频。
支持 **X(Twitter)** 和 **YouTube** 两个平台，用法完全一样——把链接扔进来就行，工具自己认平台。

## 用法

```bash
xsub https://x.com/用户名/status/123456789
xsub https://www.youtube.com/watch?v=视频ID
xsub https://youtu.be/视频ID              # 短链、/shorts/、/live/、/embed/ 都认
xsub <链接1> <链接2> ...        # 批量（可以混着来）
xsub <链接> --no-summary        # 只要字幕
xsub <链接> --allow-metered-summary   # 明知可能按 API 用量计费也要出摘要（见「隐私与费用」）
xsub <链接> --cookies           # 仅登录可见的帖子：借用 Chrome 登录态
xsub <链接> --lang zh           # 强制语言（默认自动识别）
xsub <链接> --native-subs       # 让 YouTube 也优先用平台自带字幕（X 本来就是这样）
xsub <链接> --allow-long-video  # 放行超过 2 小时的 YouTube 视频（默认拒绝）
xsub <链接> --force             # 忽略缓存重跑
xsub <链接> --open              # 完成后在 Finder 打开
```

## 输出

- X：`字幕/<日期>_<作者>_<标题>_<推文ID>_<媒体ID>/`
  （推文 ID 保证不同推文不串目录，媒体 ID 保证**同一条推文里的不同视频**不串目录）
- YouTube：`字幕/<日期>_<频道>_<标题>_<视频ID>/`
  （YouTube 一个链接就是一个视频，帖子身份和媒体身份是同一个，不重复拼两遍）

目录名里的媒体 ID 必须和真实身份**一一对应**。只有本身就绝对安全的身份
（纯小写字母数字、且放得进目录名）才原样使用；其余一律换成
「可读前缀 + 完整身份的哈希」。真实 X 媒体 ID 是 19 位纯数字，正好原样通过，
目录名不变、老的缓存不会失效。
之所以卡这么死，是因为「把身份塞进目录名」有两层会把不同身份压成同一个的操作：
**截断**（区分两个视频的尾号正好被砍掉）和**字符清洗**（`a..b` 和 `a_b` 都会变成 `a_b`）。
任何一层漏掉，两个视频就会落进同一个目录、后一个把前一个的音频/字幕/摘要整个覆盖掉，
还两次都报成功。除此之外还有两道兜底：开跑前先验一遍本轮所有视频的最终目录互不重合，
以及进目录后先确认里面已有的产物属于同一个视频——不属于就整条失败，`--force` 也不例外。
- `transcript.md` — 完整字幕，按段落分组，每段带 `[mm:ss]` 时间戳，附推文正文 / 视频简介。
  正文里的「来源」写的是**规范化后的推文链接**（不带 `/video/<n>`），所以同一个视频不管你用
  哪种写法打开，字幕正文都逐字相同——否则算出来的指纹会变，一份仍然有效的摘要会被误判成过期。
- `transcript.srt` — 标准字幕文件，可挂到播放器
- `summary.md` — 中文摘要：核心观点（带时间戳）/ 论据案例 / 金句 / 行动清单 / 追问
- `audio.m4a` + `audio.json`、`segments.json` — 缓存，带身份指纹（**平台** / 推文 ID / **媒体 ID** /
  模型 / 语言 / schema），任一项对不上或文件损坏都会自动重新生成；`--force` 会把三者一并清掉。
  manifest 里另记媒体序号、来源链接与**定位方式**（`media_source`）**备查但不参与比对**——
  同一个视频不管你用 `/status/<id>` 还是 `/status/<id>/video/1` 打开，都是同一份产物，
  不该白跑第二遍。`media_source` 记的是**工具怎么找到这个视频的**（`index` = 靠 `/video/N` 定位到、
  `url` = 整条推文只有它一个、`entry-url` = 跟着卡片给的外链重新解析、`entry-info` = 只能把条目本身
  喂给下载器），不是"X 官方把它归成哪一类"——那个信息上游并没有可靠给出，猜了只会猜错。

## 一条推文挂了多个视频（X）

X 允许一条推文放多个视频，网页上的链接末尾会带 `/video/1`、`/video/2` 这样的**媒体序号**。

- 链接带序号 → 只处理那一个视频。
- 链接不带序号、推文只有一个视频 → 直接处理。
- 链接不带序号、推文有多个视频 → **逐个解析、每个视频一个独立目录**，不会拿第一个顶包。
  混排的图片会占用序号，工具自动跳过。
- **推文里嵌的"卡片视频"也能处理**：包括外部播放器（转给对应网站的提取器）、
  推广视频、以及一条卡片里挂多个视频的情况。这类视频在 X 的数据结构里没有序号，
  用 `/video/N` 是取不到的，所以工具改成以推文的完整视频清单为准，再逐个落实到具体视频。
  这类视频的音频和字幕都**按条目单独下载**，不会拿整条推文的链接去下——那样下载器会把推文里
  每个视频写进同一个文件名互相覆盖，最后留下的很可能是另一个视频。万一条目级下载失败，
  工具**直接判这一个失败**，不会退回去下整条推文（宁可报错，也不给你一份张冠李戴的字幕）。
- 传 `/photo/N` 会被直接拒绝并说明那是图片。
- **探不明就直接失败，绝不猜**：判断"这是原生视频还是卡片视频"要靠 `/video/N` 探一下。
  探测只认两种**确定**的回答——"没有第 N 个"和"第 N 个是图片"；网络超时、解析异常这类
  "没问出结果"一律**不算**"确定没有"，整条链接当场判失败并说明是哪个序号没探明。
  否则网络抖一下，同一个视频就会被当成卡片、拿到一个下次就会变的身份，落进第二个目录白转写一遍。
- **有视频解析不出来时，整条链接判失败（退出码非零）并列出是哪几个**，不会"少处理了几个"却当成功退出。
  两个视频万一算出同一个身份（外站播放器的 ID 不受"必须是纯数字"约束），也**报错点名**，
  不会静默丢掉后一个。没有自带 ID 的卡片视频，身份放在 `xsubcard-` 这个自有前缀的命名空间里，
  避免和外站 ID 撞车。想单独处理某一个，用带序号的链接重试。
- 多视频推文里若有个别视频在后续环节失败，已成功的仍会照常产出并列在清单里，整条链接仍判失败。

## YouTube

链接怎么写都行，工具会先**归一化成 `https://www.youtube.com/watch?v=<视频ID>`** 再干活：
`youtu.be/<ID>`、`/shorts/<ID>`、`/live/<ID>`、`/embed/<ID>`、`music.youtube.com`、
`youtube-nocookie.com` 都认；`t=`（跳转时间）、`si=`、`list=`、`index=` 这些**不影响是哪个视频**的
参数一律丢掉——否则同一个视频换个分享链接就会算出第二个身份、白转写一遍。

- **只处理单个视频**：纯播放列表链接（`/playlist?list=…`，或只有 `list=` 没有 `v=`，
  以及 `/embed/videoseries?list=…` 这种嵌入写法）直接拒绝并提示改用单视频链接，
  不会闷头把整个列表下下来。
- **站点按域名白名单放行**：不在名单里的域名（含 `youtube.com.evil.example` 这类仿冒后缀）直接拒绝，
  不会顺手转给通用提取器去下一个来路不明的东西。
- **要到的必须就是要的那个**：解析结果的视频 ID 和链接里的对不上，或结果是个播放列表，一律当场失败，
  不将就用。
- 身份指纹里带**平台**字段，所以 X 和 YouTube 的 ID 再怎么撞也不会串到同一份缓存上。
- **不合适的视频在下载之前就拒**：直播和直播预告没有完整录像可转写；超过 2 小时的视频转写要跑
  很久、摘要那一步还可能超上下文，所以默认拒绝并给出提示，确认要跑加 `--allow-long-video`。
  拒绝发生在建目录和下载之前，不会先落一个空目录再报错。

### 字幕来源：两个平台的默认不一样

- **X**：有平台字幕就直接用，没有才本机转写。X 的字幕是创作者自己传的那几条，取错的余地小。
- **YouTube**：默认一律走本机 Whisper。它的自动字幕表是「一条原件 + 一百多条机器翻译」，
  而且是逐词刷屏的滚动格式，断句碎、错字多，拿去做摘要不划算。检测到有平台字幕时会提示一句，
  想用就加 `--native-subs`。

真正生效的那条策略会写进缓存指纹，所以同一个目录换一种来源重跑会自动重算，不用 `--force`。

挑轨规则（两个平台共用）：

- **人工字幕优先**，没有人工的才考虑自动字幕。
- **自动字幕只认「原语言轨」**（`en-orig` 这种）。YouTube 的自动字幕表里常年挂着 150 多条轨，
  除了原语言那条，其余全是机器翻译的——挑错一条，你拿到的是机翻的机翻。表里一旦出现 `-orig`，
  就说明这是「原件 + 机翻」的扇出：此时要的语言没有对应的原语言轨，宁可退回本机转写，
  也不拿一条同名的译轨顶包。
- **没有语言依据时宁可不用**：视频元数据没写语言、又有多条人工轨时，工具不猜，直接退回本地转写。
- 自动字幕是**滚动字幕**格式（同一句话逐词重复刷屏），会先做去重再落盘；不去重的话字幕文件里
  同样的话要重复两三遍，摘要也跟着被带偏。去重按**内容**判：一行的文字和紧挨着的前几行
  一字不差才算重抄，而且只在时间上首尾相接的字幕之间比——隔着空档又说了一遍的，照原样保留。

## 依赖

- `uv`、`ffmpeg`（已装）；Python 依赖（mlx-whisper、yt-dlp）由 `uv run --script` 首次自动安装
- Whisper 模型 `mlx-community/whisper-large-v3-turbo` 首次运行自动下载（约 1.6GB，缓存在 `~/.cache/huggingface`）
- 摘要调用 `claude -p`，走 Claude Code 的**订阅登录态**（不使用 API key）；没装 claude 则自动跳过摘要
  （能保证的边界见下面「隐私与费用」，不是"绝不产生费用"）

## 隐私与费用（重要）

| 阶段 | 数据去向 | 费用 |
|---|---|---|
| 下载音频、Whisper 转写 | **全部在本机**，音频不出本地 | 免费 |
| 生成 `summary.md` | **`transcript.md` 全文会通过 `claude -p` 发送给 Anthropic** | 走你的 **Claude Code 订阅登录态**；确认不了是订阅登录就**不出摘要**（见下） |

- 加 `--no-summary` 可完全避免任何内容外发，只留本地字幕。
- 摘要子进程被刻意收窄成「纯文本摘要器」：空临时目录当工作目录、`--tools ""` 无任何工具、
  `--strict-mcp-config` + 空 MCP 配置、`--setting-sources ""`（不加载**用户 / 项目 / 本地**这三类
  设置来源里的 CLAUDE.md、hooks、plugins、skills）、`--disable-slash-commands`、
  `--no-session-persistence`、`--max-turns 1`。
- **这不等于「绝对没有 hooks、没有 MCP」**：`--setting-sources` 能选的只有上面三类来源。
  如果你的机器上装了组织下发的 managed policy（managed settings / hooks / instructions / MCP），
  它的优先级高于命令行，这些开关覆盖不掉。装了这类策略的机器上，摘要子进程仍可能受其影响，
  甚至因为 managed MCP 与 `--strict-mcp-config` 冲突而直接启动失败（这时字幕照常产出、只是没有摘要）。
  这一条目前只做了如实说明，还没有做成自动检测。
- 环境变量走白名单：`ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_BASE_URL` /
  Bedrock、Vertex 等路由变量会被**剔除且拒绝使用**，不会因为环境里恰好有 key 就静默改走计费 API
  或第三方网关；剔除了哪些变量会在日志里明说。
- **出摘要前先验一次登录身份**：剔除环境变量只挡得住"当前终端里有 key"，挡不住你这台机器上
  早先用 `claude auth login` 存下的 **Console（按用量计费）凭据**。所以工具会先问一次
  `claude auth status`，**三项都对上**才生成摘要：登录方式是 claude.ai/OAuth、走 Anthropic 第一方、
  而且**读得到有效的订阅档位**（Pro / Max / Team / Enterprise）。只看前两项是不够的——
  实测存在"登录方式看着像订阅、订阅档位却是空的"的状态，那种状态照样按 API 计费。
  任何一项对不上就**跳过摘要并说明原因**（字幕照常产出）。日志里只记认证方式和档位，不记账号邮箱。
- **这道预检能保证什么、不能保证什么**（请按这个边界理解，别按"绝不产生账单"理解）：
  - 能保证：这次调用**不走** API key、Console 凭据、Bedrock / Vertex 或第三方网关，
    而是走你当前的订阅登录态。这一条是机械可验证的。
  - **不能保证**"一定不产生费用"：`claude auth status` 里没有任何字段能说明你的账号
    是否开了额外用量（usage credits / extra usage）、包含额度是否已经用完。这类设置一旦开启，
    超出包含额度的部分同样按 API 费率计费，而工具读不到这个状态。
  - Enterprise 等**分不清是否按量计费**的档位默认**跳过摘要**：这类账号存在"席位费只买访问权、
    用量全部另计"的形态，登录状态里区分不了，所以不替你决定。确认愿意承担可能的费用，
    就加 `--allow-metered-summary`，或设 `XSUB_ALLOW_METERED_SUMMARY=1`。
  - 完全不想有任何外发和费用风险：加 `--no-summary`，只出本地字幕。
- 字幕内容对摘要进程是**不可信数据**：system prompt 明确要求把字幕里出现的任何"指令"当素材，不执行。

## 退出码

`0` 全部成功；`1` 只要有任一链接失败（部分成功也算失败，方便脚本判断）；`130` 用户中断。

## 命令入口

`~/.local/bin/xsub` 是一行包装，指向本目录的 `xsub.py`。改 `XSUB_OUT` 环境变量可换输出根目录。

## 性能参考（M4 Pro）

32 分钟英文视频：下载约 10s，转写约 1–2 分钟，摘要约 1 分钟。

## 自动化测试

```bash
python3 tests/test_xsub.py       # 191 个用例
python3 tests/mutation_sweep.py  # 42 个变异体，必须 42/42 变红
```

191 个用例，只用 Python 标准库：`yt_dlp` / `mlx_whisper` / `claude` 全部在测试里被假冒，
不联网、不下模型、不产生任何费用。

`mutation_sweep.py` 是「测试的测试」：它把每一条保护单独拆掉一次，看测试会不会变红。
绿了就说明那条保护没有任何用例盯住，随时可能在下次重构里被悄悄删掉而没人发现。
它在临时目录里改拷贝，不会动到本仓库。

CI：`.github/workflows/tests.yml` 在每次 push 和 pull request 上跑两步——先是 191 个用例的
测试套件，然后是 42 个变异体的变异测试（任何一个变异体没被测试抓住就判失败）。两步都必须绿。
只用 Python 标准库，不装依赖、不联网、不下模型。
